## Two bugs the run surfaced

1. **The WebGPU microbench could not run on 7B.** The first six remote runs (kept above) reported `webgpu false` although Chrome had an adapter: the runtime's synthetic head weight was built by encoding a random Float32 [vocab, d] array, 2.2 GB for 7B, and the allocation failed inside the SDK's try/catch, so the planner saw no browser side. Fixed by writing random q8/q4 bytes straight into the entry layout (commit `fa52970`); the SDK now logs the failure and `measure-remote.mjs` refuses to measure without WebGPU.
2. **The bandwidth probe measured time to first byte.** It timed a 1 MiB read from the start of the fetch, so on a ~160 ms link it reported about 2 MB/s while loads ran at 20 MB/s. It now starts the clock at the first byte and reads the whole chunk (commit `b71943d`); the remote tables above show the probe after the fix.
